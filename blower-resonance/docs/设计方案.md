# 原生桌面迁移方案 V2.0

对象为汽车HVAC设计工程师。问题是候选挡位的旋转激励可能靠近壳体、支架或风道模态，手工逐组核对容易遗漏转速容差和工程规则。输入为项目来源、叶片数、转速范围、阶次、模态频率与阻尼、挡位方案；输出为交叉区间、挡位接近明细、离散扫描候选、比较、复核任务及可追溯成果。频率接近不能替代路径与根因验证。

此次目标是对既有业务作原生桌面迁移，不以扩充旧软件功能范围为立项目标。保留经测试的独立C#核心，完全替换Web表现层及HTTP下载／上传机制。依规范6.2对“以扩充功能为目标”的两倍默认门槛不适用于本次平台迁移；本次沿用通用统计口径，最低3500手写生产源码非空行。旧基线统计3527行（C#、Razor、CSS、JS）；新范围为实际构建的src下C#、XAML。测试、文档、生成源码、依赖、发布产物及材料脚本排除。最终清单见source-inventory.json。未靠重复页面、注释或空实现增加规模。

界面使用左侧纵向工程导航，中间数据工作台、右侧事务属性草稿、底部状态。模块不靠顶部按钮切换。文件、编辑、计算、导出为原生菜单，配合快捷键；图形为WPF DrawingContext绘制。支持最小1040×700窗口和区域滚动，Windows runner已检查最小窗口与原生绘图，目标硬件高DPI仍待补验。

Core：领域模型、完整校验、物理区间计算、动态规划扫描、比较、规则敏感性、质量复核、CSV交换、项目JSON及事务会话。Desktop：ViewModel实现选择、编辑草稿、撤销重做、忙碌状态、结果失效及文件编排；对话框服务隔离WPF，文件服务采用本地原子写与重开。ViewModel及文件服务链接到跨平台验证工程，测试真实生产逻辑，不把此测试算作界面运行。

迁移沿用schema=1的.blowerproj；来源、原始数据、规则和对象标识全部内嵌。旧schema1可以直接校验打开；未知版本、字段、重复属性、无效引用和错误输入整体拒绝。新软件V2.0是软件身份变化，不混同为格式升级。无需安装服务、端口或数据库。

依赖仅.NET 8和WindowsDesktop框架，无第三方运行包。Windows x64自包含发布包含运行时。Linux可交叉编译。后续已在GitHub Windows Server 2025 runner实际显示WPF窗口，检查绑定、主要业务和最小窗口，并生成18张真实原生窗口内容截图及直接exe启动记录。测试采用文件对话框适配器；实际文件选择人工交互和目标高DPI仍待补验。runner无Microsoft Word，实际分页保持未验证，不能宣称全部软著门槛通过。

备份来源：backup/pre-windows-native-20261104/blower-resonance-20261104。旧目录不合并进新分支，新分支以origin/main创建，只新增本软件目录与两份原规范。
