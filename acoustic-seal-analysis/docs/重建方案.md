## 问题、对象与工程逻辑

目标用户为车身声学试验工程师，任务是在可比条件下组织基线、单项封堵、组合封堵和恢复测量，明确每对比较的基准，区分能量均值与配对差，核查重复性及试验稳定性，形成可追溯项目和报告。位置不等同于泄漏结论，封堵前后差不等同于路径独立能量贡献，单项分贝不能相加预测组合。

本次使用C#和.NET 10，提供AcousticSeal.sln入口。Core为领域、验证、数值、事务和文件边界；App为本机Blazor Server界面，C#可观察ViewModel编排命令和编辑状态，Razor视图绑定ViewModel。浏览器作为界面宿主，不包含旧Python服务、旧JavaScript业务层。全部核心和业务编排使用C#，不限定WPF。仅监听本机回环，界面与项目不上传外部服务。

核心对象：项目元数据、封堵位置、完整工况、带来源的试验和频带、显式配对、工程参数、审计条目、复核问题。项目内嵌原始频带。每个试验关联明确工况；单项一个位置、组合至少两个；基线和恢复无位置。工况与计权、标定、单位等字段缺失或不匹配即阻断差值。数值采用明确容差。来源区分模拟、实测、人工填写与估算，混合来源禁止配对。

## 完整主流程和新增可验证能力

空白建立或从项目库打开 → 位置和工况定义 → 四类试验与结构化频带输入 → CSV映射预检和整体应用 → 用户显式逐条或批量确认配对 → 比较和复核 → 原子保存并生成备份 → 重开 → 导出HTML、CSV与分析JSON。用户可撤销/重做数据修改，项目可复制和归档，磁盘外部修改冲突阻止覆盖。导入遗留v1文件通过明确迁移映射，原文件不改。

相对旧版重点新增：真正C#解决方案与MVVM编排；实际本机文件保存和项目库；原子写、备份及文件并发冲突检测；撤销/重做与审计；旧格式迁移；结构化逐频带编辑；按筛查问题导航修复；显式批量配对预检；复核快照与CSV/JSON溯源输出。所有入口必须能够产生实际处理结果，不能靠静态页面宣称完成。
