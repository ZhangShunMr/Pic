# V2.0交付与接手索引

软件：车身声学泄漏路径与封堵试验分析软件。V2.0/内部2.0.0/schema2。以用户上传新规则dbd4c84为基线重建，所有改动仅在acoustic-seal-analysis。根目录新规则、原图片音频保留；旧V1由Git历史bf7de5e保留，不沿用旧验证。

## 启动和工程

- `AcousticSeal.sln`：解决方案入口，App为启动工程；`Directory.Build.props`/`global.json`固定.NET10环境。
- `src/AcousticSeal.Core`：领域模型与校验、数值、质量/覆盖/情景/版本核对、事务历史、CSV、迁移、保存与报告。
- `src/AcousticSeal.App`：C#可观察ViewModel、编辑器、Blazor视图及本机宿主。视图不实现核心声学计算；浏览器为本机C#程序界面。
- `README.md`/`run.sh`/`run.bat`：运行方式和典型流程。先构建sln，再运行App并访问127.0.0.1:8765。
- `.runtime/publish`为云端实际构建验证的发布输出，不提交编译产物；可按README重新publish。默认项目目录为App/Data，可由启动参数改为可写目录。

## 验证与复现

`dotnet run --project tests/AcousticSeal.Verification`执行65项C#检查，不需测试框架NuGet。`-- --emit-examples examples`生成明确模拟的项目、报告、CSV与分析JSON。夹具只用于旧格式迁移，来源说明在Fixtures/README.md。

`build-log.txt`和`publish-log.txt`为真实构建输出。`verification-log.txt`记录65项通过；`browser-evidence.json`为15步实际发布版浏览器流程；`layout-http-evidence.json`为200条长名称三种宽度分页与4项本机HTTP检查；`materials-evidence.json`和`material-build.json`记录预览页和汉字数。图表缺失/阻断、保存搬迁、未应用表单、引用和冲突均有专门检查，未验证项在验证记录中单列。

可选QA/材料生成依赖在requirements-dev.txt；生产应用不需要这些Python包。tools目录只用于独立浏览器检查、源码统计及文档生成，排除在生产行数之外。所有测试临时项目、工具链、缓存和编译产物不作为交付源码提交。

## 接手核对

先按README启动，空白建立70/67模拟配对确认3dB，再用“载入模拟案例”核对8个试验6配对，组合差4.5而不是单项相加。实际保存并从项目库重开，下载项目搬迁导入，最后核对报告中的来源、单位、参数、修订和限制。变更程序后重跑相关检查、更新真实截图和材料，再重算源码清单。
