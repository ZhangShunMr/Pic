# 交付索引与交接 V1.0

软件名称：车身声学泄漏路径与封堵试验分析软件。界面版本V1.0、内部版本1.0.0、项目格式schema1。所有内容位于仓库独立目录acoustic-seal-analysis，不使用或修改原有图片音频。

## 软件与技术交接

- `README.md`：启动环境、典型操作和边界。
- `run.sh` / `run.bat`：本机启动入口；或运行`python -m acoustic.server`。
- `acoustic/`：领域验证、事务、计算、CSV、覆盖、报告和本机HTTP服务。
- `web/`：ViewModel、服务适配、视图及响应式样式。ViewModel保存可观察状态、调用服务并通知视图，视图不实现核心声学计算。
- `docs/方案与设计.md`：立项问题、范围、架构、规模口径和风险。
- `docs/算法与文件格式.md`：公式、默认值、范围、异常、数值样例和可比性规则。
- `examples/`：明确模拟的项目、CSV和自包含报告；原始数列来源为`acoustic/demo.py`。

接手后先按README启动，空白输入一个70/67配对，再载入独立模拟样例核对8个试验和6条配对。应用所有输入后下载项目，用打开入口重开，最后导出报告。项目文件内嵌原始频带，不需要原CSV路径。

## 验证证据与复现

- `验证记录.md`、`unit-test-log.txt`：39项测试的输入、预期、实际和未执行项。
- `browser-evidence.json`：11步真实浏览器完整流程，含保存搬迁重开及导出。
- `layout-evidence.json`：200行长名称记录在三种宽度的布局探测。
- `materials-evidence.json`：16页PDF文本、截图加载和内容/页脚边界检查。
- `tests/`：可重跑的核心与HTTP测试；不计入生产源码量。
- `tools/source_inventory.py`：重算源码规模；`build_materials.py`生成材料，`verify_materials.py`检查预览，后两者仅为交付工具。
- `tools/browser_verify.py`与`layout_verify.py`：真实Chromium流程和布局探测，需要测试专用Playwright；不属于生产依赖。

目录`.runtime/`仅存测试临时下载、页面缩略图及布局样例，已忽略不提交。服务器不持久保存用户项目；用户在浏览器下载后自行保管。后续修改算法、界面或标签时，应重跑相关测试、更新截图和材料，再重算源码清单。不要只改手册而不改程序。
